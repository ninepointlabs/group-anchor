# Group Anchor

A Manifest V3 browser extension that keeps tab groups anchored at the top of
the tab strip, directly below pinned tabs.

Tab groups can't be pinned, so as you open new tabs they drift down the tab
list. Group Anchor keeps every window in this order:

**pinned tabs → tab groups → ungrouped tabs**

It's built for Chrome and Chromium-based browsers (Brave, Edge, Vivaldi),
including Brave's vertical tab sidebar. Plain JavaScript, no build step, no
dependencies.

## Install (unpacked)

### Chrome / Edge

1. Clone or download this repository.
2. Open `chrome://extensions` (Edge: `edge://extensions`).
3. Turn on **Developer mode**.
4. Click **Load unpacked** and select the repository folder (the one that
   contains `manifest.json`).

### Brave

1. Clone or download this repository.
2. Open `brave://extensions`.
3. Turn on **Developer mode** (top right).
4. Click **Load unpacked** and select the repository folder.

Pin the extension's toolbar icon if you want quick access to its settings.

## Settings

Click the toolbar icon:

- **Enabled**: global on/off, synced across your browsers via
  `chrome.storage.sync`. While off, the icon shows an `OFF` badge.
- **Pause for this window**: stops anchoring in the current window only.
  Stored in `chrome.storage.session`, so it lasts until the window closes or
  the browser restarts.

## How it works

The service worker (`background.js`) listens for tab and group events
(created, moved, attached, detached, removed, pinned/unpinned, regrouped,
group created/updated/moved, new window), plus browser startup and install.

For each affected window it waits ~200 ms so a burst of events turns into one
pass, then:

1. Reads the window's tabs with `chrome.tabs.query`.
2. Works out the groups' current order from where they appear in the strip.
   Groups are never sorted, so if you drag one group above another, that new
   order is kept.
3. Checks whether the groups already sit contiguously right after the pinned
   tabs. If so, it does nothing. This is what prevents flicker and stops the
   extension's own moves from triggering endless passes.
4. Otherwise it moves the first misplaced group with
   `chrome.tabGroups.move(groupId, { index })`, where `index` starts at the
   pinned tab count and advances by each group's tab count, then re-reads the
   window and repeats until the order is right.

Other details:

- A per-window busy flag stops passes overlapping. Events that arrive during a
  pass queue exactly one follow-up pass.
- "Tabs cannot be edited right now (user may be dragging a tab)" is retried
  with backoff (100, 250, 500, 1000, 2000 ms). When the drag ends, the browser
  fires a move event that triggers a fresh pass anyway.
- "No group with id" / "No tab with id" errors (something closed mid-pass) are
  ignored, since the close fires its own event.
- Only windows of type `normal` are touched (not popups or app windows).
- No state that matters lives in memory. The service worker can be stopped at
  any time; each pass derives everything from the current tabs.

Permissions: `tabs`, `tabGroups`, `storage`. Nothing else.

## Known limitations

- **Pinned tabs can't be grouped.** That's a browser rule. Pinning a grouped
  tab removes it from its group.
- **New tabs may join a group.** A tab opened from a tab inside a group (for
  example by middle-clicking a link) can be added to that group by the
  browser. That's browser behavior, not something the extension does. The
  group stays anchored either way.
- **Ungrouped tabs placed between groups get moved below them.** If you drag an
  ungrouped tab into the group area, the groups after it move up past it.
- **Vivaldi** uses its own tab stacks in its UI. Tab groups created through the
  Chrome API may not map onto them, so behavior there is untested.

## Development

- Icons in `icons/` are placeholders generated by `node scripts/make-icons.js`
  (no dependencies). The extension itself doesn't need the script.
- `npm test` runs both test suites:
  - `npm run test:unit` (`tests/error-handling.mjs`) runs `background.js` in
    Node against a stubbed `chrome` object. It checks the drag-error retry and
    that tabs or groups closing mid-pass are ignored. It needs no install and
    no browser.
  - `npm run test:integration` (`tests/integration.mjs`) loads the extension
    into headless Chromium with a throwaway profile and checks tab ordering,
    settings and the popup. It needs `npm install` (Playwright is the only dev
    dependency) and a Chromium: either run `npx playwright install chromium`,
    or point at a system build with `CHROMIUM_PATH=/usr/bin/chromium`. Set
    `SCREENSHOT=popup.png` to save a screenshot of the popup.
- `package.json` and `node_modules/` are dev-only and nothing in the extension
  references them. The folder still loads unpacked with them present.
- See [TESTING.md](TESTING.md) for the manual test checklist and what has been
  verified so far.
